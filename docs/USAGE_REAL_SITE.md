# 真实对局使用方法

## 进入页面时

打开 `/multi` 或 `/multi/room` 后，即使还没匹配到对手，也会显示：

- 状态：等待对局
- 题库：646
- 监听：运行中
- 当前 URL
- 自己的棋盘：尚未发现

这表示脚本正在等页面出现你的结果表，不会猜隐藏答案或读取浏览器存储。只有你明确点击“提交当前猜测”时，助手才会操作原网页的提交按钮。

## 有棋盘后

1. 正常在游戏里完成一条猜测。
2. 助手会优先用“我的猜测”标签自动绑定自己的棋盘。
3. 如果页面上有多个独立候选棋盘，点击“选择我的棋盘”，再点击带临时边框的那一张；这次点击会被助手拦截，不会触发游戏操作。
4. 每出现一条自己的新行，助手只读取昵称以外的七个字段，以及年龄、Major 冠军数、Major 次数的箭头。

读取成功后，悬浮窗会显示“已合并 N 次可见猜测”、剩余候选，以及“立即猜”或“最佳探针”。历史行按严格逻辑 AND 累积，而不是按相似度打分。

## 填入下一猜

点击“填入下一猜”后，助手会：

1. 找到页面搜索框；
2. 用原生输入事件写入推荐昵称；
3. 等待真实下拉候选；
4. 只在 `playerId` 或昵称加国家/队伍等信息能唯一确定时选择该项。

## 随机首猜与提交

新局尚无反馈时，点击“随机首猜并填入”会从 646 人题库中随机选择一名选手，并沿用相同的唯一选项校验。它只负责填入和选中。

核对昵称后点击“提交当前猜测”。助手会再次确认：

- 搜索框仍是刚才唯一选中的昵称；
- 原网页只有一个可信的“提交猜测”按钮；
- 按钮没有被禁用；
- 当前没有上一猜正在等待反馈。

任一条件不满足时都不会点击页面按钮。提交成功后按钮会锁定，直到自己的棋盘出现新的反馈行。

如果有两个同名选手（例如两个 `Zero`），没有唯一 `playerId` 或足够唯一的附加信息时会停止，不会随便选择第一项。

## 遇到未知颜色、箭头或棋盘

不再有单独的“反馈校准页面”，也不需要手工标颜色。助手会保留此前已经合并的历史，把最新一行标为“最新反馈尚未识别”，并在 DOM 继续渲染、页面变更或你点击“扫描页面”时自动重试。

重试期间会暂时禁用“填入下一猜”，避免基于不完整反馈操作。如果状态持续不恢复，请点击：

1. “采集诊断”查看当前发现数量；
2. “复制诊断”直接粘贴 JSON 到本任务，或“下载诊断 JSON”后发送文件内容；
3. 保留游戏页面，不需要提供 Cookie、Token、账号信息或浏览器存储。

诊断只保留候选元素的精简结构、可见文本、class/data/aria 属性、尺寸、最近 DOM 变更和错误；会排除聊天、密码字段、Cookie、Token 与浏览器存储。

## 当前验证边界

真实房间诊断已经确认：自己的棋盘是 `.player-board-self`，对方棋盘是 `.player-board-opponent` 且含 `.masked-cell`；反馈色使用 `correct/close/wrong`，数字方向使用 `lucide-arrow-up/down` SVG。修复后的本地真实结构回放已验证双棋盘只绑定自己、扫描不丢历史、未知反馈自动恢复、随机首猜、唯一项选择、用户点击提交与防重复提交。

真实网站的下拉唯一选择和提交按钮点击仍需要下一局现场确认。完整清单见 [实现与验证清单](implementation-validation.md)。
